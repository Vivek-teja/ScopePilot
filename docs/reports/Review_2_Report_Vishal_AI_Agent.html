1. Executive Summary & Objective

The primary goal of Review 2 is to prove the end-to-end request/response contract with deterministic, reproducible behavior before introducing probabilistic LLMs or vector embeddings.

Review 2 Focus: Construct a rule-based mock engine that accepts approved proposal scope items and deliverables alongside incoming client change requests. Exercise the five required case categories: (1) clearly in scope, (2) clearly out of scope, (3) partial overlap, (4) ambiguous request, and (5) insufficient evidence.

3. Architecture & Deterministic Mock Engine

The mock service (backend/src/ai/services/changeAnalysisMock.service.js) applies strict contract validation and deterministic heuristics:

Client Request Payload ---> Zod Input Schema Validation (ChangeAnalysisInputSchema) | v +-------------------------------------------------------------------------------+ | Deterministic Heuristic Reasoner (ChangeAnalysisMockService) | | 1. Insufficient Evidence Detection: checks for unreferenced external ERP/SAP | | 2. Ambiguity Detection: flags subjective adjectives (faster, enhance, etc.) | | 3. Deliverable Overlap: matches against approved DEL-CAT-01, DEL-CHK-01 | | 4. Out-of-Scope Capability Detection: flags Web3, CSV ingest, background sync | | 5. Classification Matrix: in_scope / out_of_scope / partial / clarification | +-------------------------------------------------------------------------------+ | v Zod Output Schema Validation ---> Structured Consistent JSON (ChangeAnalysisOutputSchema)
Honesty & Safeguards: For Ambiguous (Case 4) and Insufficient Evidence (Case 5) requests, the engine deliberately avoids forcing artificial certainty. It generates targeted clarifying questions for the client and returns lowered confidence scores (45%–60%).

8. Questions Prepared for Mentor Evaluation

Mentor Question Prepared Technical Response
Why not use an LLM immediately? A rule-based mock helps the team confirm the contract, validate edge cases, and establish predictable baseline behavior without adding model latency, costs, or non-deterministic variance.
What is partial overlap? Part of the request is covered by existing deliverables (e.g. Catalog UI), while other parts introduce substantial new work (e.g. bulk CSV processing or background sync) that require extra pricing and scheduling.
What does the mock prove? It proves the end-to-end data pipeline, Zod schema validation, case handling across 5 distinct outcomes, and client response structure before semantic AI is added.
