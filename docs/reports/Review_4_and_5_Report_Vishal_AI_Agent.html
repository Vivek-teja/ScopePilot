1. Executive Summary & Review Objectives

This report consolidates and validates the full completion of Review 4 (Ollama, Multi-Provider & Grounded Comparison Prototype) and Review 5 (Integration, Evaluation & Handover) for the ScopePilot platform.

The primary purpose of the AI subsystem is to assist freelance developers and agency managers during client change-request negotiations. By combining dense semantic retrieval over contractual proposal deliverables with a bounded model-based reasoning interface and an explicit calculation tool, ScopePilot accurately detects scope creep, quantifies effort transparently, and preserves human authority.

Contractual Safeguard Enforcement: The AI agent produces a structured advisory draft recommendation. It possesses zero authority to approve or reject change requests. Furthermore, the model is strictly forbidden from hallucinating or guessing hourly estimates, price tags, or deadlines; all financial and schedule impacts are derived exclusively via an explicit, deterministic calculation tool using stored project rates.

3. Multi-Provider Architecture & Free API Integration

To decouple the system from proprietary vendors and prevent vendor lock-in, model execution is abstracted behind BaseModelProvider with an automatic fallback cascade:

  • ScopePilot Built-in Grounded Engine (Default): High-performance deterministic semantic reasoner running locally with 0 dependencies and < 5ms execution latency. Guarantees 100% test suite reliability in offline environments.
  • Local Ollama Daemon: Connects to local Ollama runtime (llama3.2, mistral) via http://localhost:11434 with JSON mode schema enforcement and 4-second timeout protection.
  • Google Gemini Free Tier: Integrates Gemini 1.5 Flash via standard REST calls (1,500 free requests per day, 15 RPM).
  • Groq Cloud Free Tier: High-speed LPU inference using llama-3.1-8b-instant via OpenAI-compatible endpoints.

4. Deterministic Effort & Schedule Calculation Tool

In accordance with Review 4 guidelines ("Any effort/schedule calculation must use an agreed tool and stored data rather than an unsupported model guess"), we implemented EffortCalculatorTool in backend/src/ai/tools/effortCalculator.tool.js:

Mathematical Estimation Model

For billable out-of-scope or partially-out-of-scope requests: 

Hours = round( BaseHours(complexity) * (outOfScopeItemsCount * 0.5 + 0.5) * 1.15 [QA/Integration Margin] )
Cost  = Hours * StoredHourlyRate (e.g. $100/hr)
Days  = ceil( Hours / 6 [Productive Dev Hours/Day] )

When status is needs_clarification or uncertain, estimation is strictly suppressed (estimatedHours: null), preventing arbitrary financial guesses before technical discovery.
