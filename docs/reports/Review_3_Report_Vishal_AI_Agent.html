1. Executive Summary & Review 3 Objective

In real-world software consulting engagements, clients propose change requests using colloquial, informal terminology that diverges significantly from the formal technical language of signed proposals. For example, while the proposal states "E.164 international telephone number formatting on checkout", a client writes "cellphone dial code picker on the final buying screen". Strict keyword queries completely fail on these requests.

Review 3 Deliverable Goals:
• Corpus Management: Chunk approved scope items and deliverables with strict source audit references (sourceReference, proposalVersion, documentType).
• Dense Vector Embeddings: Implement 1024-dimensional normalized vector embeddings with subword character n-grams and domain synonym clusters to bridge vocabulary gaps.
• Evidence-Aware Semantic Search: Calculate cosine similarity against baseline passages and categorize results into confidence bands (strong_match, weak_match, no_evidence).
• Failure Analysis & Safe Fallbacks: Document cases where candidate proximity is weak or evidence is missing, triggering safe fallbacks to uncertain rather than guessing.

2. Architectural Data Flow & Safeguards

The retrieval pipeline evaluates natural-language requests against baseline deliverables before passing candidates to human decision-makers:

Critical Safety Principle: A similarity score is purely a retrieval signal indicating semantic proximity. A high score identifies candidate evidence for review but does not constitute proof that the work is contractually included. Human approval remains exclusively reserved for authenticated project participants via POST /api/change-requests/:id/decision.

5. Comprehensive Failure Analysis & Safe Fallbacks

A. Resolving Vocabulary Discrepancies (EXP-01 & EXP-02)

When the client queries for "cellphone dial code picker" or "filter goods by price bracket", traditional keyword string searching yields 0% overlap with "E.164 telephone format" or "product catalog faceted search". Subword character n-grams and domain synonym clusters in embedding.service.js project these expressions into overlapping dense coordinates, achieving 69% and 94% similarity and correctly retrieving the relevant baseline deliverables.

B. Guarding Against False Scope Inclusions in Partial Overlaps (EXP-03)

In EXP-03, the client asks for SMS text messages and push notifications. Naive AI systems frequently observe the word "notification" and falsely declare the request in scope. Our engine scores the candidate in the weak band (50%), returning status: "weak_evidence" and attaching actionable clarifying questions: 

"Top candidate DEL-NOTIF-01 matched with moderate similarity (50%), but contains significant semantic divergence from approved deliverables. Does this request extend existing deliverable DEL-NOTIF-01 or introduce a distinct technical service?"

C. Out-of-Scope Distractor Nearest Neighbors (EXP-04)

When evaluating cryptocurrency and Web3 requests, vector search identifies DEL-PAY-01 (Stripe payment gateway) as the closest vector neighbor due to payment concepts. The system detects that the score falls in the weak band (44%), enforces the advisory notice that proximity is not contract approval, and prompts for a formal change-order estimate.

D. Zero-Evidence Uncertain Fallback (EXP-05)

When a request references proprietary on-premise infrastructure (AS400 warehouse connectors, VPN tunnels) with zero documentation in the approved baseline, similarity scores drop to 13% (well below the 35% minimum threshold). The engine clears candidates (topMatch: null), returns status: "uncertain", and generates technical discovery questions for client engineering.

9. Mentor Evaluation Questions & Prepared Answers

Mentor Question Prepared Technical Response
What does semantic search add over keyword matching? Semantic search retrieves candidate approved scope items even when the client uses informal phrasing, synonyms, or colloquial terminology (e.g. "cellphone dial code" → "E.164 telephone format") that would completely miss keyword queries.
Does a high similarity score prove the work is included? No. A similarity score is purely a retrieval signal indicating lexical and conceptual proximity. The comparison engine and human decision-makers must evaluate the evidence, and the system retains uncertainty where requirements diverge.
Why keep source and version references? Source references (DEL-CHK-01, proposalVersion: 1) guarantee auditability. When the AI agent presents candidate evidence, reviewers and project leads can verify the exact contractual document backing the analysis.
What happens when the client request has zero baseline evidence? When similarity scores fall below the threshold (< 0.35), the engine triggers an uncertain fallback: it returns status: "uncertain", clears false candidates (topMatch: null), and outputs structured discovery questions.
