1. Executive Summary & Problem Solved

In freelance client-contractor engagements, scope creep is the primary source of project delays, budget overruns, and contractual disputes. Clients frequently introduce additions informally via chat or email, and freelancers often accept them without evaluating divergence from the agreed project baseline.

ScopePilot AI Agent Solution: ScopePilot introduces an automated change-analysis agent that evaluates incoming client requests against approved proposal scopes (ProposalVersion) and deliverables (Deliverable) before extra work is accepted.
• Review 1 Milestone: Established strict architectural boundaries, inspected existing domain schemas, and authored typed Zod input/output contracts.
• Review 2 Milestone: Built a deterministic rule-based mock engine proving reproducible contract behavior across 5 required canonical case outcomes before introducing probabilistic LLMs.

2. Review 1 Summary: Architecture, Schemas & Contracts

The AI subsystem is strictly partitioned inside backend/src/ai/ to avoid coupling with business controllers, financial transactions, or route handlers:

Domain Entity Code Location Role & Attributes Leveraged by AI Agent
ProposalVersion src/modules/proposal/proposal.model.js Immutable scope snapshot: versionNumber, title, scopeSummary, scopeItems: [{ title, description, estimatedHours, price }], status: 'approved', contentHash.
Deliverable src/modules/deliverable/deliverable.model.js Auditable baseline units: scopeReference (e.g. DEL-CAT-01), title, description, acceptanceCriteria: [string].
ChangeRequest src/modules/changeRequest/changeRequest.model.js Target persistence container with AI extensions: aiAnalysis: { summary, confidenceScore, rawOutput, analyzedAt }, scopeComparison: { outOfScopeItems, inScopeItems, similarityScore }.
Decision & Project src/modules/project/project.model.js currentApprovedProposal, freelancer, client. Final human sign-off via decisionService.

Formal Zod Input & Output Contracts (aiAnalysis.contract.js)

  • Input Contract (ChangeAnalysisInputSchema): Requires projectId, approvedProposalVersion (version number, summary, scope items), array of deliverables (audit scopeReference, criteria), and newClientRequest (title, description). Rejects malformed requests upfront.
  • Output Contract (ChangeAnalysisOutputSchema): Enforces structured evaluation fields: summary, reviewStatus enum, confidenceScore (0.0–1.0), inScopeItems, outOfScopeItems, uncertainItems, affectedDeliverables, evidence, recommendations, and mandatory disclaimer.
Review 1 Human Authority Boundary: The AI provides an advisory draft only. Final decisions to approve, reject, or renegotiate changes remain exclusively with authenticated humans. Financial adjustments and schedule dates are computed deterministically, never hallucinated by AI.

6. HTTP Mock Routes & Controller Architecture

HTTP endpoints are mounted under /api/ai/* in backend/src/routes.js:

  • GET /api/ai/cases — Discovery endpoint listing all 5 canonical cases with metadata and sample requests.
  • GET /api/ai/cases/:caseId — Fetches full input payload and rationale for a single case.
  • POST /api/ai/cases/:caseId/run (and GET) — Runs mock analysis on a named canonical case.
  • GET /api/ai/cases/run-all — Batch executes all 5 cases and returns an aggregated health report.
  • POST /api/ai/analyze-mock — Accepts dynamic payloads, validated with validate({ body: ChangeAnalysisInputSchema }) and optionalAuth middleware.

10. Mentor Evaluation Questions & Answers (Reviews 1 & 2)

Mentor Question Prepared Technical Response
Why start with an input/output contract before the model? Defining Zod schemas first establishes an immutable boundary between frontend consumers and the backend engine. It allows teams to mock and build dashboards in parallel without waiting for LLM or RAG infrastructure.
Why use a rule-based mock before an LLM? A rule-based mock helps the team confirm the contract, validate edge cases, and establish predictable baseline behavior without adding model latency, costs, or non-deterministic variance.
Can the AI agent approve a change request autonomously? No. ScopePilot enforces strict human authority. The agent produces an evidence-based draft and risk classification; only the authenticated client and freelancer can make binding decisions via POST /api/change-requests/:id/decision.
What is partial overlap? Part of the request is covered by existing deliverables (e.g. Catalog UI), while other parts introduce substantial new work (e.g. bulk CSV processing or background sync) that require extra pricing and scheduling.
What happens when scope evidence is missing or ambiguous? The engine refuses to guess or hallucinate. It marks reviewStatus as needs_clarification / uncertain, lists uncertainItems, and generates targeted questions for the client.
